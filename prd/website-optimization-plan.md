# CC Usage 官网展示优化方案

## 核心原则

官网沿用现有区块顺序、卡片网格和标签页位置。产品画面直接从同级仓库 `cc-usage/frontend` 构建，嵌入真实的 `IslandWindow`、`MainPanelWindow`、`UsageAreaChart` 和请求日志组件；官网不另画灵动岛、面板卡片或 SVG。浏览器预览内置的数据是设计示例，访客不会连接到自己的本机数据。

```text
首页首屏       真实灵动岛收缩 / 展开 / 停靠循环
灵动岛展示     真实展开态 → 原有四张功能卡
主面板展示     真实总览面板：额度、Token 统计、趋势、日志与设置入口
数字摘要       原有四组产品数据
功能区         原有卡片网格，补齐八类能力说明和完整文档入口
详情标签页     真实趋势图 / 真实请求日志 / 真实连接与额度
技术、平台、服务商、FAQ、上手与下载   沿用现有顺序
```

## 真实前端接入

1. `scripts/build-desktop-preview.mjs` 从 `cc-usage/frontend` 构建浏览器预览，输出到官网 `public/desktop-preview`，官网生产构建一并打包。
2. `ActualFrontendFrame` 只负责 iframe 容器、官网主题同步、隐藏桌面项目仅供开发的预览导航，以及切换产品组件本身提供的形态和滚动位置。
3. 展开与停靠调用产品预览中的原生交互按钮；趋势与日志定位产品总览中的真实章节。演示数字及视觉形态都由产品前端提供。
   首屏进入视口后自动循环三种形态；离开视口即停，系统开启减少动态效果时保持静态。
4. GitHub Pages 工作流同时检出桌面端仓库并构建前端。官网构建时也可通过 `CC_USAGE_FRONTEND_DIR` 指向桌面端 `frontend` 目录。

## 功能覆盖

| 功能域 | 首页展示 | 详细说明 |
|---|---|---|
| 灵动岛与托盘 | 首屏循环演示收缩、展开、贴边三态；展示区保留展开态与原功能卡 | 文档说明四边吸附、托盘与后台行为 |
| 平台来源 | 原八张平台卡 | 文档说明来源与字段限制 |
| 连接与套餐 | 真实总览与连接额度标签 | 文档说明 Auth、API、连接启用与代理 |
| 额度和余额 | 产品额度卡与状态 | 文档区分订阅窗口、API 余额与未知 |
| Token、趋势、费用 | 产品统计卡与原生 SVG | 文档解释输入、输出、缓存和费用口径 |
| 请求日志 | 产品真实日志表 | 文档说明筛选、分页、异常与未知值 |
| 设置与数据 | 产品主面板设置入口、功能卡 | 文档说明偏好、导入导出与清理 |
| 更新与隐私 | 原技术、FAQ 与下载区 | 文档说明本地存储和应用更新 |

## 验收

- 首屏自动展示三个灵动岛形态，展示区的完整展开态由 `cc-usage` 原组件渲染。
- 主面板、趋势 SVG、日志和连接额度均来自同一产品前端，没有官网另造的组件顶替。
- 既有页面结构、卡片位置及标签页保留；详细功能可从首页进入文档。
- 桌面端预览与官网的 TypeScript、Vite 生产构建通过，宽屏和窄屏不截断关键内容。
